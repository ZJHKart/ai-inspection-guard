# 智能巡检 · 区域入侵检测（AI Inspection Guard）

浏览器端的"虚拟警戒区"入侵检测工具：载入现场图像（单张或一组），自动识别人员与车辆，判断是否越过预设警戒区，把越界目标登记为报警记录并可导出。全部推理在本地浏览器内完成，图像不上传。

**课程**：《人工智能基础与应用》期末作品
**在线演示**：https://zjhkart.github.io/ai-inspection-guard/
**技术栈**：原生 HTML / CSS / JavaScript + MediaPipe Tasks Vision（WASM）+ EfficientDet-Lite0（INT8）

---

## 1. 功能

| 模块 | 说明 |
| --- | --- |
| 图像输入 | 拖拽 / 点击上传 / 粘贴剪贴板 / 3 个内置示例场景；多选或一次拖入多张自动进入批量模式 |
| 目标检测 | COCO 80 类，默认关注人员、轿车、卡车、客车，可扩展到摩托车、自行车与其他物体 |
| 警戒区 | 画布上直接拖拽移动、八向缩放、一键重绘；坐标以归一化比例保存，与分辨率无关 |
| 入侵判定 | 三种判据：落地点（目标框底边中点）、中心点、目标框落入区域的面积占比 ≥ 15% |
| 报警记录 | 按置信度排序，含落点坐标、批次、时间；导出 CSV（UTF-8 BOM，Excel 直开） |
| 批量检测 | 一次处理多张图像，逐张给出目标数 / 越界数 / 耗时，汇总表可导出 |
| 历史归档 | 单张与批量结果写入 localStorage，刷新不丢，可整表导出或清空 |
| 参数联动 | 阈值、类别、判据改动后**即时重算**，不重新推理 |
| 容错 | 模型加载失败可一键重试；本地 `file://` 打开时给出说明层而不是白屏 |

## 2. 技术方案

```
图像 → 等比缩放（最长边 1280）→ EfficientDet-Lite0(INT8) 推理（阈值 0.05 粗筛）
     → 置信度 + 类别二次过滤 → 几何判定（落地点 / 中心点 / 重叠率）
     → 画布绘制 + 报警登记 + 历史写入
```

- **检测模型**：EfficientDet-Lite0，COCO 80 类，INT8 量化，约 4.6 MB；CPU 单帧约 100 ms，不需要 GPU 与后端。
- **判定逻辑**：取目标框底边中点作为"落地点"，等价于判断"人站在哪里"；相比中心点判据，可避免远处目标框体上沿越界造成的误触发。
- **阈值分层**：模型层放宽到 0.05 并缓存原始结果，界面滑杆只在缓存上二次筛选，因此调参零成本，也使得阈值扫描实验成为可能。
- **默认阈值 0.30**：由 9 张评测图、15 个目标的扫描实验得出（F1 峰值 0.867），见 `samples/eval/README.md`。
- **零外部依赖**：模型、WASM 运行时全部放在 `vendor/` 内，不走任何 CDN。

## 4. 本地运行

浏览器安全策略禁止 `file://` 加载 WASM 与 ES 模块，必须通过 HTTP 访问：

```bash
python -m http.server 8000      # 或 npx serve .
# 打开 http://localhost:8000
```

单元测试（判定逻辑，无需浏览器）：

```bash
npm test                        # node --test tests/zone.test.mjs
```

## 6. 部署

纯静态站点，无构建步骤。推送到 GitHub 仓库后，在 `Settings → Pages` 选择 `main` 分支根目录即可。

## 7. 已知局限

1. **叉车等工程车辆不在 COCO 类别内**，会被识别为 `truck` / `motorcycle` 一类近似类别；这是类别体系的限制，不是阈值问题。
2. 远距离小目标（画面高度占比 < 8%）与暗光条件下召回明显下降；评测中唯一的漏检即属于此情形。
3. 单帧静态图像没有时序信息，无法区分"路过"与"驻留"，不做目标跟踪与去重。
4. 警戒区只支持单个矩形，斜向通道需用外接矩形近似。
5. 评测为计数级、样本量 9 张，不能替代标准数据集上的 mAP 评测。
6. 批量模式顺序执行，未使用 Web Worker，处理大量图像时界面会有轻微卡顿。
